## 2. 一轮请求的数据流（主轴）

```
平台 POST /invocations {sessionId, prompt, eventId, attempt}
  → [A] invocations.ts 取四元组 → [B] run(sessionId, prompt, eventId, attempt)
      [B] 同 sessionId 排队；全局满 → SDK 直接 503
      [B] spawn 前调 [C] recall()（300ms 超时降级为空）+ 取 env 白名单
      [B] spawn `dsh --profile agentrun -`，stdin 写 prompt
        → [D] startup 解析 task → runner 读 env → turn 判重 → create/resume agent
            → 跑一轮，stdout 写 NDJSON 帧 → final + flush（mock DataLake）+ 退出码
      [B] 逐行解析 stdout 成帧流，按退出码判成败
  → [A] invocations 只取 final → 返回 {result, sessionId}
      ws 透传帧；a2a/agui 经 SDK 把帧翻译成协议事件
```

模块间接口只有三个：A↔B 是 `run()` 调用；B↔D 是"spawn 参数 + stdin + env + stdout 帧"；
C 启动期把一切准备好（profile/patch/env），运行期给 B 提供 recall 结果与 env。

## 3. 公共契约（先定再动工）

### 3.1 帧协议（D 生产 → B 解析 → A 消费）

stdout 一行一个 JSON（NDJSON），8 种帧（issue #6 §3.4）：

| 帧 | 时机 | 关键字段 |
| --- | --- | --- |
| `session` | 开头一次 | `sessionId`、`cwd` |
| `status` | 阶段变化 | `phase`：turn_start / step_start / step_end / turn_end |
| `delta` | 每收到一个 token | `kind`、`text`、`attemptId`、`revision` |
| `tool_call` | 发起工具调用 | `callId`、`tool`、`input` |
| `tool_result` | 工具返回 | `callId`、`status`、`result` |
| `question` | 请求用户确认 | `callId`、`questions`、`timeoutSec` |
| `final` | 结尾一次 | `text`、`reason`、`sessionId` |
| `error` | 失败 | `message` |

归属：SDK 现状无帧模型（已核实）。帧类型先在 `shared/src/frames.ts` 定义，SDK 的
A2A/AG-UI 消费同一份——需与 SDK 团队对齐，避免两边各写一套。帧字段命名不带 DSH 词汇。

### 3.2 spawn 接口（B → D）

```
命令:   dsh --profile agentrun -        # `-` = task 从 stdin 读（headless-startup 原生语义，
                                        #   已核实 packages/bundle/headless/src/startup.ts:65）
stdin:  prompt 纯文本，写完关闭
env:    C 组装的白名单（§3.4）；sessionId/eventId/attempt 走 AGENTRUN_* 变量
stdout: NDJSON 帧（§3.1）
stderr: 诊断日志，B 收集，失败时并入 error 信息
退出码: 0=completed，1=失败（D 定，B 判）
```

sessionId 走 env 不走 argv：patch 行 `sessionId: !!js process.env.AGENTRUN_DSH_SESSION_ID || ''`
（issue #6 §3.6）。沿用官方 `headless-startup` 行解析 task，只换 driver 行。

### 3.3 agent_metadata 字段去向（issue #7 → C）

| issue #7 字段 | 去向 |
| --- | --- |
| `system_prompt` | → env/patch → D 注册到 `ctx.systemPrompt` 的 `deployment:persona-prefix` 段 |
| `allowed_tools` | → C 渲染 `{{TOOLS_ALLOW}}` → `agentrun-context` 行 → D context.ts 执行白名单 |
| `model_config.name/base_url/api_key` | → C 渲染 `{{MODEL_NAME}}`（provider 固定 `deepseek-official`）+ env `DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` |
| `model_config.credential_provider_name` | api_key 为空时 → C 经 SDK identity（agentidentity）取凭据 |
| `mcp_gateway_config.endpoint/auth_*` | → C 渲染 `{{MCP_SERVERS}}`：每上游一行 `dsh-mcp-client`（streamable-http，Authorization 头） |
| `memory_config.endpoint/api_key/公私网域名` | → C recall.ts（SDK memory 客户端）；**凭证不进子进程**，只有召回结果进 |
| `skills`（`/home/service/.jiuwen`）、jiuwen 专用字段 | jiuwen 遗留，DSH 不适用的忽略；skills 映射本期缓做 |

### 3.4 env 白名单（C 组装 → B 透传 → D 消费）

固定名单（issue #6 §3.5）：`DSH_HOME`、`PATH`、`HOME`、`NODE_ENV`、`TZ`、`LANG`、
`AGENTRUN_*`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`MCP_*_URL`、DataLake 端点与凭证。
**不全量继承** Adapter 环境（召回凭证留在 Adapter 进程内）。

`AGENTRUN_*` 变量名是我们自己的契约，在 `shared/src/env.ts` 定义（建议值）：

| 变量 | 用途 |
| --- | --- |
| `AGENTRUN_DSH_SESSION_ID` | 会话 id（设计已定名） |
| `AGENTRUN_EVENT_ID` | 幂等键 |
| `AGENTRUN_ATTEMPT` | 重投次数 |
| `AGENTRUN_SYSTEM_PROMPT` | 平台系统提示词 |
| `AGENTRUN_RECALL_RESULT` | 召回结果（JSON） |

### 3.5 LaunchSpec（B 的解耦缝）

B.run 不硬编码 dsh 命令，spawn 参数由 C 的 DSH 半边注入：

```ts
interface LaunchSpec {
    command: string
    args: string[]
    env: Record<string, string>
    encodeStdin(task: string): string
}
```

换 harness 时只换 LaunchSpec 与 D，A/B/SDK 不动（见 §5）。

## 4. 模块分解（文件级）

### A 协议层（`adapter/src/handlers/` + `main.ts`）

SDK 注册 API 已核实（`packages/agentarts-sdk/src/sdk/runtime/app.ts`）：
`app.entrypoint(fn)` / `app.ping(fn)` / `app.websocket(fn)` / `app.asyncTask(fn)`；
A2A/AG-UI 将是 `app.a2a` / `app.agui` 风格（SDK 团队 11/30 交付）。

| 文件 | 具体写什么 |
| --- | --- |
| `main.ts` | 只做装配：C 的 config → B 的 scheduler → 注册 handlers → SDK listen，不放业务逻辑 |
| `handlers/invocations.ts` | `app.entrypoint((payload, ctx) => …)`：解四元组 → 调 B.run → **只取 final 帧** → 返回 `{result, sessionId}` |
| `handlers/ws.ts` | `app.websocket`：连接生命周期，帧透传，收到 final/done 结束 |
| `handlers/a2a.ts` | 建 task 记录（taskId↔sessionId 映射）→ B.run → status 帧驱动状态迁移、final 写产物置完成、question 置"需要输入"、异常置失败 |
| `handlers/agui.ts` | 绑处理器产帧流；帧 → AG-UI 事件翻译在 SDK（delta→文本增量、tool_call→工具事件、question→等待输入、final→run 结束） |

SDK 现成行为（不用自己写，已核实）：`maxConcurrency` 默认 15、满载 503、`/ping`
HealthyBusy、SSE `data: {json}\n\n`、响应头 `x-hw-agentarts-session-id`
（`model.ts:8`、`app.ts:941`）。

依赖：invocations/ws 现在就能写；a2a/agui 依赖 SDK 新面，可先按 §3.1 写帧消费逻辑，
SDK 到位后接线。**与 SDK 团队确认**：A2A/AG-UI 面与 `/invocations` 共享同一个
`maxConcurrency` 计数器（issue #6 §4.4）。

验证：三套协议各通一条；invocations 返回形状/响应头对齐 Python 版。

### B 并发控制（`adapter/src/scheduler/`）

**全局上限不用自己写**——SDK `maxConcurrency` 已实现计数、满载 503、HealthyBusy。
B 只写两个文件：

| 文件 | 具体写什么 |
| --- | --- |
| `session-queue.ts` | `Map<sessionId, Promise 链>`：同 sessionId 排队串行，一个会话同一时刻只有一个子进程；不同会话并行 |
| `run.ts` | 调 C.recall（300ms 降级）→ 拿 C 的 env/LaunchSpec → spawn（§3.2）→ stdin 写 prompt → **stdout 按行切 NDJSON 解析成帧流**（异步迭代器交 A）→ stderr 收集 → 退出码判定（非 0 / 无 final / 启动失败 = 失败）→ 超时 kill → 释放队列 |

验证：同 sessionId 并发请求串行；同 eventId 重投正确送进 D（B 不缓存结果，判重在 D：
重投会再 spawn 一个子进程，但 D 返回旧结果、不重复执行）；子进程异常退出判失败；超时回收。

### C 注入 + 启动器（`adapter/src/` + `shared/`）

| 文件 | 具体写什么 |
| --- | --- |
| `config.ts` | 读 agent_metadata JSON（§3.3），优先级 argv > env > 挂载文件 > 默认；api_key 为空时经 SDK identity 按 `credential_provider_name` 取凭据；产出类型化 RuntimeConfig |
| `patch.ts` | 渲染 `profile/cordis.patch.yml.tmpl` 占位符（`{{MODEL_PROVIDER}}/{{MODEL_NAME}}/{{MCP_SERVERS}}/{{TOOLS_ALLOW}}/{{DELTAS}}/{{JSON}}`）→ 写入 `$DSH_HOME/profiles/agentrun/` → 校验；启动时渲染一次（设计决策 4） |
| `recall.ts` | SDK memory 客户端查记忆/知识库，**300ms 超时、失败降级为空**，结果交 B 注入 env |
| `ops.ts`（启动器） | 启动时序：写 profile 三件套到 `$DSH_HOME` → `dsh plugin --profile agentrun add`（装 driver 包 + mock DataLake 包；**装包 ≠ 进树**，进树靠 patch 行）→ 调 patch.ts 渲染 → `dsh --profile agentrun --dump-config` 校验预期行 → reconcile 幂等重入；插件接口、快照 |
| `shared/src/env.ts` | `AGENTRUN_*` 常量 + 白名单组装函数（§3.4）+ LaunchSpec 构造（§3.5），A/B/D 共用 |
| `shared/src/frames.ts` | 帧类型（§3.1），与 SDK 团队对齐后成为公共契约 |

验证：render-check 断言 headless-runner 关、agentrun-runner 在；配置优先级 UT；
recall 超时降级 UT。

### D headless 子进程（`plugin/` + `profile/` + mock DataLake + smoke）

沿 **DSH 官方服务抽象**（`SessionPersistence` / `AttachmentStore` / `StorageBackend` +
`systemPrompt` 服务 + patch 行）拆两人，不共同编辑任何文件：

| | **D1 执行链（关键路径）** | **D2 存储与能力注入** |
| --- | --- | --- |
| 文件 | `plugin/src/runner.ts`（建/接管 agent、订阅 assistant-stream 逐 chunk 产帧、退出码）、`turn.ts`（eventId 幂等三态）、`profile/` 三件套 + patch 模板、`scripts/smoke.mjs`（fake model） | mock DataLake 插件（三后端）、`plugin/src/context.ts`（allowTools/身份）、`capability.ts`（召回注入 + system_prompt 落 persona-prefix 段） |
| 起步方式 | **直接用官方 JSONL 后端开发**（base 默认自带），不等 D2 | 对着官方抽象 + 参照 JSONL 实现写 mock，独立可测 |
| 验收 | smoke 出 delta/final；同 eventId 只执行一次 | **过官方 live-write 契约**；allowTools 拦截生效；system_prompt 出现在装配后提示词 |
| 难点 | 流订阅时序、帧契约实现、幂等（难但窄） | 三后端面广，但各有官方参照实现与契约测试兜底（广但浅） |

D1 runner 要点：行 `inject: [agentDefaultModel, agents, sessions]`；读
`headlessStartup.task` + env sessionId/eventId → turn 判重 → `agents.create`/`resume` →
订阅 `agent/assistant-stream` 逐 chunk 写 delta（官方只出块级 text，这是自研 driver 的
根本原因，`json-stream.ts:275-276` 已核实）→ 工具事件写 tool_call/tool_result →
`ask_user_question`（timed）写 question 帧后本轮正常结束 → final → flush →
按 `reason.kind === 'completed'` 退出 0/1。

D1 turn 判重三态：会话事件中找同 `source.eventId` 的 user message——有且有 turn/end →
直接返回旧结果；有但无终态 → 异常轮（不静默重跑，返回明确错误）；无 → 执行新轮。

D2 mock 要点：三后端实现 `SessionPersistence`（create/open/flush/stat/list）、
`AttachmentStore`、`StorageBackend.kv`；**存储根目录必须在 `DSH_HOME` 之外**（模拟外部
持久存储，否则"清 DSH_HOME 续会话"测试不成立）；env 预留真插件端点/凭证变量名
（待 DataLake 团队定）。

D1 patch 行清单（`cordis.patch.yml.tmpl`，**模板归 D1 独占**，D2 以行片段交付）：

| 动作 | 行 | 说明 |
| --- | --- | --- |
| 关 | `headless-runner`、`ptc-runtime`、`workflow-ptc`、`tool-workflow` | `tool-executor-ptc` 在 base 本就 disabled，不用写 |
| 关 + 插 | `session-persistence-jsonl` / `attachment-local` / `storage-json` → mock DataLake 三行 + `storage-domain` 路由改 | D2 交付行片段与包名 |
| 改 | `agent-default-model` | provider/model 占位符 |
| 插 | `agentrun-runner` / `agentrun-context`（allowTools）/ `agentrun-capability` / 每上游一行 `dsh-mcp-client` | runner 的 sessionId 走 env，json/deltas 启动期渲染 |

1. patch 模板归 D1 独占，D2 交付"行片段 + 包名 + exports 子路径"，避免两人改一个文件。

## 5. 耦合边界与多 harness 复用

解耦缝是**帧契约**：帧契约以上与 harness 无关，以下每个 harness 各写一份。

| 模块 | 与 DSH 的耦合点 | 换 codex/hermes 时 |
| --- | --- | --- |
| A 协议层 | 无（消费帧 + 平台四元组，翻译在 SDK） | 原样复用 |
| B 并发控制 | queue/帧解析/退出判定/超时通用；耦合在 spawn 细节（命令、stdin 语义、env 名） | 大部分复用，换 LaunchSpec 即可 |
| C 注入+启动器 | config/recall 是平台契约，通用；**patch/ops 是 DSH 专有**（Cordis 树、patch 行、`!!js`、三件套、`dsh plugin add`）；env 白名单机制通用、名单内容专有 | config/recall 复用；patch/ops 每 harness 重写 |
| D 子进程 | 全部专有（职责所在） | 每 harness 写一份新 D |

引入新 harness 的工作量 = 新 D（driver 产帧）+ 新 LaunchSpec + 新装配渲染器
（C 的 harness 半边）；A/B/SDK/C 平台半边不动。

**现在不为多 harness 建抽象**（YAGNI），只留两个便宜的缝：

1. 帧类型放 shared，命名不带 DSH 词汇；
2. B.run 的 spawn 参数经 LaunchSpec 注入，不硬编码。

边界提醒："每轮一个子进程 + stdin 文本任务"是 DSH headless 语义；codex exec 形态相近；
若将来某 harness 是常驻进程或 SDK 内嵌形态，B 的进程模型需扩展——现在不预设。
