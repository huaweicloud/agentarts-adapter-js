- **BUG-06** [已修复]（按用户修订方案实施）：
  - run.ts：runRound 增加 signal 参数与幂等 cancel()，spawn 前检查 aborted；
    首个终止原因只记录一次（failReason ??=）；取消先 SIGTERM、宽限 CANCEL_GRACE_MS=5000
    后 SIGKILL（DSH SIGTERM 清理路径可能以 0 退出，仍判失败）；outcome 在子进程实际
    close 后结算，队列名额随之释放。导出 cancelledHandle 供排队取消路径复用。
  - Scheduler.run(req, signal?)：入队 job 先查 aborted（排队期间取消跳过
    recall/launchSpec/spawn），spawn 前由 runRound 兜底再查。
  - ws.ts：AbortController 在入队前建立 + ws.raw.once('close') 监听 + ws.closed 预检；
    final 帧扣住，待 outcome 确认 flush 完成、进程成功退出后再发（保护收到 final
    立即关闭的客户端）；finally 清监听 + 幂等 abort。
  - a2a.ts：退订不取消任务（finally 只解绑）；TaskRegistry.bind 携带 AbortController，
    新增 registry.cancel(taskId) 作为显式 CancelTask 入口（SDK A2A 面交付后接线）。
  - agui.ts：AguiRunInput.signal 透传（按 SDK run 约定接线，待交付）。
  - fixture：hang 永不自行退出、stubborn 忽略 SIGTERM、normal 在 final 后退出前写
    flush 标记文件。

    A2A 退订任务继续且显式取消可终止挂起轮次）；ws 取消断言直接查 outcome.error，
    不凭耗时。测试等待改为首帧真实到达（消除固定 sleep 竞态）。
  - 验证：adapter 55 测试全过 ×2 遍，覆盖率 98.78%，tsc 零错误。
  - 遗留：child.kill() 只覆盖直接子进程，SSH 远端取消 12/30 单独验收；

    message），裸 final → invalid → 协议破坏路径判失败。

  - ws/a2a/agui：转发非终态帧 → await outcome → 恰好一个终态；ws 的 pendingFinal
    与三处无条件补发删除。invocations 不变。
